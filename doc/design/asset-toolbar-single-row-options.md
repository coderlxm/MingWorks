# 资产管理筛选栏单行布局：待选方案

## 目标与当前阶段

将截图中的两层工具栏收为一行，给下方表格释放高度，保留现有搜索、可见性、标签、格式、日期范围、清空及视图切换能力。本轮只提供选项，用户选择后再修改界面；不涉及提交和部署。

## 源码事实

- `web/src/components/journal/AssetManagementToolbar.vue` 将视图切换和搜索放在 `toolbar__main`，其余筛选放在独立的 `toolbar__details`，因此桌面端两行是结构设计，不是偶然换行。
- 当前 760–1119px 的媒体规则会进一步拆分筛选；759px 以下通过第二层的“筛选”按钮展开面板，仍会占用文档流高度。
- `web/src/components/journal/private-feed/PrivateAssetFeedView.vue` 的表格布局使用 `auto auto minmax(0, 1fr)`，工具栏变矮可以直接释放表格所在行的空间，无须调整表格高度算法。
- 工具栏通过 `apply` 和 `changeView` 通知父组件。筛选变更沿用 350ms 合并触发和中文输入法处理，父组件负责数据加载及回到第一页。

以上是源码结论；下文尺寸是设计建议，不是对截图像素或线上实际高度的测量。

## 方案 A：筛选入口全部保留，紧凑单行（推荐）

桌面排列：

```text
[瀑布｜表格] [主题或正文……] [全部权限 ▾] [标签…] [全部格式 ▾] [日期范围 ▾] [清空]
```

### 布局

- 视图切换保留图标和文字；搜索占据剩余空间，不再独占一整行。
- “全部 / 私有 / 加密 / 公开”改为一个可见性下拉入口，显示当前值，例如“私有”。
- 标签输入和格式选择直接保留在这一行。
- 两个日期输入收成一个“日期范围”按钮。点击后在浮层内显示起止日期，支持只填一端；选中后按钮显示范围摘要，过长截断，完整日期在浮层中可见。
- 清空保持独立入口，未设置条件时禁用。
- 桌面控件建议高 36–40px，工具栏含上下内边距约 56–64px；沿用当前配色、圆角和选中态。

### 空间安排

以工具栏可用宽度而非屏幕物理分辨率为依据。完整排列初步按约 1140px 以上设计：视图约 160px、搜索至少 220px、权限约 100px、标签约 120px、格式约 120px、日期约 190px、清空约 48px，其余留给间距与内边距。最终宽度随实际字体和现有控件确定。

更窄时，标签、格式和日期整体进入“筛选”浮层，搜索和可见性仍在主行；手机端可见性也进入浮层，视图切换保留带无障碍名称的图标按钮。所有尺寸下主工具栏不换行，不引入页面横向滚动。

### 取舍

- 优点：桌面仍能直接看到每类条件的入口和大多数当前值，符合原界面操作习惯；搜索与筛选共享原本闲置的横向空间。
- 代价：切换权限以及填写日期各多一次打开操作；窄屏需要集中式筛选入口。
- 适合：希望主要改变布局密度，而非改变筛选的使用方式。

## 方案 B：常用条件常驻，其余放入“更多筛选”

桌面排列：

```text
[瀑布｜表格] [主题或正文…………] [全部 私有 加密 公开] [更多筛选 · 2] [清空]
```

### 布局

- 搜索和现有四个可见性按钮常驻，权限仍可单击切换。
- 标签、格式、起止日期放进“更多筛选”浮层；浮层内完整显示字段标签和当前值。
- “更多筛选 · N”只统计收纳在该入口内的生效条件：标签、格式、日期范围各算一项，起止日期合计一项。无条件时不显示数字，有条件时高亮按钮。
- 搜索和权限不计入这个数字，避免重复计数。不新增第二行条件标签或摘要。
- 高度目标与方案 A 相同。可用宽度不足时，四个权限按钮变成下拉；手机端权限一起进入筛选浮层，主行只保留视图、搜索、筛选入口，清空移到浮层内。

### 取舍

- 优点：搜索空间更充裕，视觉更简洁；桌面权限切换仍然直接。
- 代价：标签、格式、日期的具体值不能同时直接看到，需要打开面板；这些条件若常用，会增加点击次数。
- 适合：平时以搜索和权限筛选为主，较少使用其他条件。当前没有使用频率证据，这只是该方案的适用前提。

## 两种方案共同的交互约束

1. 浮层覆盖内容而不参与工具栏高度计算，打开或关闭不改变表格位置；浮层需避免被当前工具栏及表格容器的 `overflow: hidden` 裁切。
2. 保持现有自动生效语义，不引入另一套“暂存—应用”流程。打开面板本身不请求数据；修改字段才按现有事件路径应用。
3. 面板提供“关闭”而不是“取消”：关闭不会撤销已生效筛选。再次打开保留当前条件；输入后立即关闭也不丢弃已排队的变更。
4. 清空一次清除所有条件，包含隐藏在浮层中的条件；不改变瀑布/表格视图。方案 B 的计数同步清零。
5. 切换视图、从详情返回及外部标签筛选继续走已有状态路径；不得因面板显隐重置筛选、重建结果区域或触发整页加载。
6. 筛选数据更新时工具栏保持可操作，沿用结果区域自身的加载呈现。只改变布局，不重写请求和缓存逻辑。
7. 浮层支持键盘打开、Escape 关闭和关闭后焦点返回；窄屏浮层内容可内部滚动，不能推高主工具栏。图标按钮保留清晰的可访问名称。

## 最小实现边界

- 主改 `web/src/components/journal/AssetManagementToolbar.vue`：合并主行、调整控件呈现与面板显隐；保留 `filters`、`view` props 和 `apply`、`changeView` 事件契约。
- 仅在窄屏需要图标布局时调整 `web/src/components/journal/AssetViewSwitch.vue`，不影响其他使用位置。
- 优先复用项目已有组件能力，不因本次布局增加依赖。具体浮层组件及其公开 API、安装版本和本地解析情况，在选定方案后的实现阶段核对，不在本方案中预设未经核实的组件调用。
- 不调整父级页面的数据管理、表格列、分页、后端接口及数据库，不重构其他筛选栏。
- 依据 Vue 最佳实践，继续使用现有组件内状态和显式事件，不引入全局状态、额外监听或通用筛选框架。

## 建议与待选项

推荐 **A**：用户当前明确希望节省纵向空间，并未要求隐藏筛选功能；A 对既有操作入口的保留更充分。若更看重简洁、愿意把标签/格式/日期收起来，则选 **B**。

本轮只需选择 A 或 B；无需先决定颜色、字号或底层组件。
