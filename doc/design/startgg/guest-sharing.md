# FTG 全站只读访客模式

状态：用户已批准实施，并授权完成 P0/P1 审查与修复后提交、推送触发部署。
日期：2026-09-21。
源码基线：`47d6f60`。
应用：`apps/startgg-dashboard/`。
地址：`https://ftg.xmcloud.buzz`。

## 1. 用户已明确的需求

**这个看板的比赛信息没有隐私限制。任何人都可以直接进入，什么都能看，只是不能执行管理操作。无需主人管理分享。**

本方案以这条最新需求为准，完整替换此前按项目开启分享的设计。

- 站点首页默认就是可直接浏览的比赛看板，不先显示口令登录页。
- 访客可查看全部已记录项目、历史对局、关注选手、种子、决赛和关注配置。
- 比赛期间、非比赛期间、监控暂停后都可以进入，比赛完赛不影响阅读。
- 主人输入现有站点口令后，才出现管理功能并获得操作权限。
- 不增加分享开关、项目公开状态、分享表、随机链接、访问期限或访客账号。

分享网站首页或任意项目的现有 URL 即可，不需要生成链接或执行发布操作。

## 2. 入口与浏览体验

### 2.1 默认进入

访问 `https://ftg.xmcloud.buzz`，直接看到现有比赛总览。访问 `/events/:eventId`，直接看到对应项目；访问 `/following`，直接查看关注信息。

沿用现有路径，不增加独立的 `/guest` 页面，也不复制一套访客看板。未登录即为访客，这使站点本身成为始终可用的访客入口。

顶部显示“访客 · 只读”，旁边保留不抢眼的“管理登录”。访客无需先选择模式、输入口令或点击其他确认。

### 2.2 所有阅读能力开放

| 内容或行为 | 访客体验 |
| --- | --- |
| 比赛总览和赛事导航 | 可查看、切换全部已记录项目 |
| 最近对局和历史赛果 | 可查看对阵、比分、轮次、时间和胜者 |
| 关注选手 | 可查看关注标记、选手状态及相关比赛 |
| 种子与决赛 | 可查看已有名单、阶段对局和最终排名 |
| 关注管理页 | 可查看选手、游戏偏好、本届关注和种子档位；页面标题在访客模式称为“关注信息” |
| 页签、筛选、搜索、分页 | 照常使用，只改变阅读视图 |
| start.gg 原站入口 | 照常打开 |
| 重新读取、连接恢复 | 只读取已有本地结果，不发起上游采集 |

不因访客身份隐藏比赛、历史记录、关注名单或偏好。数据范围与主人看到的比赛看板相同，区别是能否执行管理操作。

### 2.3 非比赛期间

- 没有进行中比赛时，继续展示最近赛果和历史项目。
- 项目完赛后仍可回看，既有项目地址继续可用。
- 主人暂停监控时，访客仍可浏览，页面显示暂停状态及数据采集时间。
- 尚无任何项目时，显示正常空态；访客不出现“发现赛事”操作按钮，站点仍可进入。
- 项目确实被主人清空后，该项目链接显示记录不存在，并提供返回总览的入口。

不设置比赛时间窗口，不因为没有正在进行的对局就关闭入口。

## 3. 登录与管理操作

“管理登录”打开当前页面上的口令面板，复用现有站点口令、签名 Cookie 和会话期限。

登录成功后保留当前项目、页签、筛选、已加载内容及阅读位置，在原页面显示管理控件。口令错误仅反馈在面板中，不影响比赛浏览。

登录后顶部提供“退出管理”。退出后回到同一页面的访客状态，保留比赛内容，不跳回阻断阅读的登录页。会话过期同样仅失去管理权限，页面继续可读。

需要登录的操作包括：

- 发现赛事、启动或切换监控项目。
- 长期关注、本届关注、不关注等偏好修改。
- 查找并添加关注选手。
- 修改种子关注档位。
- 立即同步、暂停和恢复监控。
- 今后新增的其他配置修改或业务写入。

访客不显示上述按钮、输入表单和操作抽屉。以现有功能为准，不为此次需求新增管理能力。

“筛选对局”“翻页”“重新读取页面数据”属于阅读；“立即同步”会触发采集和潜在消息推送，属于管理。这一区分必须在界面和服务端保持一致。

## 4. 服务端权限

### 4.1 开放现有比赛读取接口

不新增一套访客 API，直接让现有阅读接口免登录可用：

| 接口 | 未登录访问 |
| --- | --- |
| `GET /api/session` | 可读取当前是否有管理会话 |
| `GET /api/startgg/board` | 可读取总览和比赛状态 |
| `GET /api/startgg/events/:eventId` | 可读取任意已记录项目详情 |
| `GET /api/startgg/events/:eventId/sets` | 可读取及筛选该项目的已采集赛果 |
| `GET /api/startgg/following` | 可读取关注选手、偏好和种子档位等信息 |

管理任务的 `/operations/:operationId` 继续供已登录管理流程使用。任务结果不是比赛数据，访客页面无需获取或展示操作进度、赛事发现结果和管理报错。

总览中的比赛、选手和采集状态字段两种模式一致；仅供管理操作追踪的 `operation` 不向访客返回有效任务内容。无需为比赛资料建立字段可见性配置或另一套读模型。

### 4.2 拒绝未登录操作

外层 Fastify 服务按“明确列出的阅读路由可匿名，其余业务路由要求主人会话”执行权限判断。新增接口不会因为使用 GET 就自动开放。

- 现有 `/api/startgg/*` 业务写接口继续要求有效的主人 Cookie。
- 未登录调用这些接口直接返回 401，不转发给 bot，不入队，不产生数据库修改或消息推送。
- `/api/session` 的登录、退出仍按现有会话逻辑处理，登录必须提供正确口令。
- 保留现有写操作 Origin 校验。
- bot 内部 API 继续绑定回环地址并要求内部 Bearer Token；浏览器不接触这个 Token。

页面隐藏管理控件和服务端拒绝未授权操作同时成立，不把前端状态当作权限依据。这里仅有访客和现有单用户主人两种使用状态，不增加账号、角色管理或复杂授权系统。

## 5. 前端数据与状态调整

继续复用现有 `App.vue`、比赛组件和 `useBoardData`，不建立第二套访客页面。

当前 `useBoardData` 把全部数据读取绑定在 `authenticated === true` 上，退出时还会清空全部比赛内容；这些行为需要改为：

1. 读取比赛数据不要求主人登录。身份读取与比赛读取独立，身份读取失败也明确显示其错误，不把未知身份视为已登录。
2. `authenticated` 仅表示能否显示管理控件、发起业务操作和追踪管理任务，不决定比赛页面是否存在。
3. 登录、退出或会话失效时，清理操作任务、候选结果和管理抽屉状态，保留比赛数据与阅读状态。
4. 已经发出的管理请求若在退出后返回，不得重新显示管理状态；沿用请求代次约束。
5. 会话过期导致写操作返回 401 时，提示“管理会话已过期”，停止该管理动作；比赛读取照常进行。
6. 总览、详情、关注信息及分页组件继续使用同一套公开读取接口，不增加分享记录查询。

主人操作抽屉仅在有效管理会话中挂载。对局筛选、页签和分页继续作为普通阅读组件，不受管理模式切换影响。

## 6. 刷新和数据语义

保留现有比赛阅读规则：

- 可见页面每 5 秒读取本地结果；页面隐藏时暂停周期读取。
- 比分和已有对局状态原位更新；新增对局提示点击查看，避免阅读时突然重排。
- 已加载内容和历史分页复用，不用整页刷新表现数据更新。
- 页面读取失败明确暴露，保留标注时间的已加载内容；用户可以手动重新连接，不新增自动重试。
- 采集暂停、采集失败和官方完赛分别呈现，不把暂停更新说成比赛结束。
- 访客浏览和读取更新不会调用 start.gg 上游，不提高采集频率，也不会触发 Telegram 推送。

依然只展示系统已采集的数据。访客“什么都能看”指现有看板的数据范围，不承诺完整签表、所有参赛选手或未采集的历史。

当前源码依据：`server/server.mjs` 的统一登录代理、`App.vue` 的登录页分支、`useBoardData.ts` 的身份读取约束，以及 `dashboardApi.ts` 的现有路由。这些读取事实以 `47d6f60` 为基线；实施前应核对当时实际源码。

| 场景 | 预期结果 |
| --- | --- |
| 未登录打开首页 | 直接看到比赛总览，可见管理登录入口 |
| 未登录打开任意已有项目或关注信息页 | 可直接阅读，无口令阻挡 |
| 比赛结束、监控暂停或非比赛期间 | 入口仍可用，历史赛果照常展示 |
| 无比赛记录 | 显示正常空态，不要求访客配置监控 |
| 访客筛选、搜索、翻页和读取更新 | 正常工作，不触发业务写入 |
| 访客自行请求同步、暂停、关注或设置接口 | 返回 401，业务状态和推送不变 |
| 主人登录 | 当前页面出现管理功能，阅读状态保留 |
| 主人退出或会话过期 | 当前页面转为只读，比赛内容保留 |
| 退出后旧管理请求返回 | 不恢复管理抽屉、任务或候选结果 |
| 页面连接或采集失败 | 明确显示对应问题及数据时间，不冒充成功 |

此次只解决“整个看板可看、管理操作需登录”。此前讨论的平板全屏展示、保持亮屏和自动轮播不在本轮范围内。
