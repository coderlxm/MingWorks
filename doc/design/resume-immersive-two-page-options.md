# 个人简历：沉浸式双页阅读方案

## 1. 本轮目标与范围

从「关于我 → 个人简历」进入后，隐藏网站顶部 Header、左侧导航以及手机底部导航，让简历占据浏览器内容区。PDF 默认左右并排展示两页，按组翻页，提供清晰、始终可见的退出入口。

本轮为设计选择，不修改功能代码。以下提供两个完整的视觉与交互方向，用户选定后再实施。

主目标是「完整展示一组两页、尽量不滚动」，不是模拟真实纸书，也不是修改简历文件本身。

## 2. 当前实现依据

以下来自当前源码，而非历史设计文档：

| 位置 | 当前行为 | 对本次设计的影响 |
| --- | --- | --- |
| `web/src/components/about/AboutResumeCard.vue` | 入口链接指向 `/resume` | 保留现有入口和分享地址 |
| `web/src/App.vue` | 简历使用公共页面框架；照片、游戏已有沉浸布局判断 | 简历可增加独立布局分支，不需要另建网站或窗口 |
| `web/src/components/app/AppRouteViewport.vue` | 内容容器纵向可滚动，子内容默认不收缩 | 只隐藏 Header 不够，还需要让简历舞台真正受可用高度约束 |
| `web/src/components/resume/ResumeView.vue` | 负责加载、口令解锁、分享令牌兑换；内容宽度上限 960px，并有上下留白 | 保留访问流程，调整承载布局 |
| `web/src/components/resume/PdfResumeViewer.vue` | 桌面一次显示一页；图片按宽度缩放、高度自适应；手机隐藏预览，显示文件操作卡片 | 改成按宽高共同约束的双页舞台，手机也需提供站内阅读 |
| `src/journal-server/resumePreview.ts` | PDF 使用 216 DPI 生成逐页浅色、深色 WebP 图片 | 复用现有预览资源，不新增 PDF 解析流程 |
| `web/src/types.ts` 的 `JournalResumePreviewPage` | 已有页码、宽高及两种主题的图片 URL | 足以计算双页比例、页组和适屏尺寸 |

当前组件使用图片预览，不具备 PDF 文字层、文内链接点击和文本选择能力；本次双页布局不会自动增加这些能力。保留主动打开原件和下载入口。

本文不推断线上简历的实际页数、纸张尺寸或正文清晰度。

## 3. 「类似全屏」的定义

两个方案都采用**网页内沉浸模式**：占满浏览器内容区域，隐藏本站导航；浏览器地址栏、标签栏仍由浏览器管理。

这符合“点击即进入”的需求，也适用于口令解锁和直接打开分享链接。浏览器原生全屏需要用户激活，并受浏览器权限及支持情况约束，不应把异步加载完成后自动进入原生全屏当作主路径。参见 [MDN：requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)。

本轮不增加原生全屏按钮，不引入全屏权限失败后的替代流程。

## 4. 方案 A：极简双页展板（推荐）

定位：像一个专门用于展示简历的阅读台，以内容面积和快速浏览为主。

```text
┌────────────────── 浏览器内容区 ────────────────────┐
│ 个人简历                          [更多] [退出阅读 ×] │
│                                                    │
│      ┌────────────────┐  ┌────────────────┐       │
│      │                │  │                │       │
│      │     第 1 页     │  │     第 2 页     │       │
│      │                │  │                │       │
│      │                │  │                │       │
│      └────────────────┘  └────────────────┘       │
│                                                    │
│          [上一组]   1–2 / 共 4 页   [下一组]         │
└────────────────────────────────────────────────────┘
```

### 视觉与操作

- 浅色模式使用现有暖灰背景；两张纸平行并排，保留约 12–20px 间距和轻微边界，不添加厚重外框。
- 不再重复展示当前头像、文件元信息横条、底部 Dock、页码圆点和键盘提示等多层区域。
- 顶部保留约 40–44px 的阅读操作条：短标题、更多、退出。它是阅读器控制栏，不是本站 Header。
- 底部约 36–40px，统一放上一组、范围页码、下一组；按钮不盖住正文。
- 页面默认完整适屏，两页始终正面显示；翻页只做简短淡入淡出，或直接切换，不旋转纸张。
- 点击某一页进入该页的放大阅读，提供「返回双页」入口；这属于用户主动查看细节，不改变默认双页浏览方式。

### 取舍

- 两页是独立的内容板，视觉克制，适合招聘者快速查看。
- 折叠屏联想来自左右并排结构，不强调书脊和翻书动作。
- 实现重点在布局与页组切换，动效改动较少。

## 5. 方案 B：对开折叠书册

定位：强化“两块页面围绕中缝展开”的视觉，接近用户描述的折叠屏。

```text
┌────────────────── 浏览器内容区 ────────────────────┐
│                                      [退出阅读 ×]  │
│                                                    │
│       ┌─────────────────┬─────────────────┐        │
│       │                 ║                 │        │
│       │     第 1 页      ║      第 2 页     │        │
│       │                 ║                 │        │
│       └─────────────────┴─────────────────┘        │
│                                                    │
│         [上一组]  1–2 / 共 4 页  [下一组] [更多]     │
└────────────────────────────────────────────────────┘
```

### 视觉与操作

- 两页组成整体书册，中间约 6–10px 的窄缝，外侧轻描边或阴影；中缝装饰只在页外，不覆盖简历文字。
- 静止时两页完全展开、保持正面，不对正文施加透视变形。
- 退出独立固定在右上安全区域；底部一条紧凑控制栏集中翻页、范围页码和更多操作，不自动消失。
- 翻组可做约 200–260ms 的整体轻微开合与淡入过渡，仍然一次切换两页，不逐张翻动，不模拟封面。
- 遵循系统减少动态效果的偏好时直接切换。翻页状态不得依赖动画结束事件才能解除。
- 点击页面同样进入放大阅读，返回后保留当前页组。

### 取舍

- 整体性更强，更接近双屏展开的观感。
- 相比 A，多出中缝、整体外框与转场设计；需要控制装饰强度，避免影响正文辨识。
- 不使用 WebGL、Canvas 翻书引擎或新增翻页依赖；视觉通过现有 Vue 与 CSS 能力完成。

## 6. 两个方案共同的行为规则

### 6.1 进入、解锁和退出

1. 点击简历卡片进入 `/resume`，立即呈现沉浸框架，不先展示普通简历页再跳成全屏。
2. 公开或已获授权时，加载完成直接展示第一组；受口令保护时，在同一框架中显示现有解锁界面。解锁期间也始终保留退出入口。
3. 分享链接直接访问、刷新 `/resume` 与卡片进入采用同一阅读布局；临时分享令牌继续按现有方式兑换和清理，不拼接到页面图片 URL。
4. 建议「退出阅读」明确返回 `/about`，与当前简历返回入口一致；不通过不确定的浏览器历史猜测去向。浏览器自身后退仍保留正常历史语义。
5. 从关于我进入并退出后，恢复其已有滚动位置及简历卡片焦点；直接访问简历后退出，则展示关于我页面。实施时沿用现有滚动恢复机制，不重写全站历史管理。
6. 退出和重新进入构成新一次阅读，默认回第一组；本次阅读内放大、缩小、换主题和调整窗口尺寸不重置页组。
7. Escape 在单页放大时返回双页；在双页模式时退出阅读。有打开的更多菜单时先关闭菜单，不一次执行多级退出。

### 6.2 页组定义

按连续页对分组：第 1 组为 1–2，第 2 组为 3–4，以此类推；不使用“封面单页、内页对开”的书籍规则。

| PDF 页数 | 第一次展示 | 后续展示 |
| --- | --- | --- |
| 1 页 | 单页居中，无虚构第二页 | 不显示翻组控件 |
| 2 页 | 1–2 | 禁用上一组、下一组 |
| 3 页 | 1–2 | 3 + 右侧空位 |
| 4 页 | 1–2 | 3–4 |
| 5 页 | 1–2 | 3–4，再到 5 + 右侧空位 |

奇数尾页保持左侧位置、页面尺寸和中缝位置不变，右侧只留空背景，不补假页、不重复上一页。页码显示真实范围，如「第 3 页 / 共 3 页」，不显示不存在的第 4 页。

默认没有连续纵向页面列表。上一组、下一组、方向键和 PageUp / PageDown 每次移动一组；首尾不循环。输入框、口令框和菜单正在操作时不截获它们的键盘行为。不把滚轮动作转换成翻页，以免触控板误触。

### 6.3 适屏与可读性

- 阅读器占据可用动态视口高度，先扣除控制栏、安全边距，再计算舞台；宽度不再受 960px 限制。
- 所有页面保持原始宽高比，完整显示，不裁剪、不拉伸。不能简单地把两张原有宽度的图片并排。
- 根据预览宽高计算统一页槽：整份文档以最大宽高比确定所需槽宽，两槽并排、统一高度约束；每页在槽内等比容纳。这样不同页尺寸、奇数尾页和切换页组不会导致舞台忽大忽小。
- 默认适屏状态不出现阅读区域横纵滚动条；放大阅读允许在局部区域滚动，控制栏和退出入口不随正文滚走。
- “不滚动即可看全”与“任意设备上小字仍足够大”无法同时保证。手机竖屏强制显示两页时尤其如此；不能以裁掉底部或过度锐化掩盖问题。
- **本方案严格保留手机默认双页，不自动改成单页。** 提供主动点击页面放大及「返回双页」，横屏后重新按可用宽高适配；不强制旋转设备。
- 图片预览的清晰度上限由现有资源决定。本次不调整服务端生成规格，不增加上传或重新生成操作。

### 6.4 更多操作与现有能力

「更多」收纳原件查看、下载、已有条件下的复制分享链接，以及已有联系方式，避免新增常驻信息块压缩阅读舞台。退出不能收进更多菜单。

打开原 PDF、下载和分享都是用户主动操作；图片加载失败不自动跳到原件，不静默换成另一种阅读模式。

深浅主题沿用现有对应预览图。图片中的文字仍不是可选择文本；不以本次界面调整承诺 PDF 文本层或屏幕阅读器全文能力。翻页控件、退出按钮和页码本身提供可访问名称和键盘焦点。

### 6.5 加载与连续操作

- 框架和控制栏常驻；首次加载只在舞台展示进度，读取失败在舞台明确显示错误并保留退出。
- 一组两页共同就绪后再提交页组切换；等待期间仍显示原页组，不能一页先换、一页仍旧。
- 切换等待时暂时禁止再次翻组，不加入重试或请求队列。失败明确展示，恢复操作状态；错误不能被解释为翻页成功。
- 已加载图片继续复用；翻页、放大、退出放大及窗口变化不重新请求简历元信息、不重复解锁。
- 定位尺寸和页组就绪状态不能依赖动画结束回调；无动效、转场中退出、组件卸载都要直接释放对应交互状态和事件。

## 7. 实现边界与组件职责

依据 Vue 最佳实践，把页面框架、授权编排、页组展示和控制栏分开；不引入新的全局状态库或通用阅读器框架。

| 位置 | 建议职责及变更 |
| --- | --- |
| `App.vue` | 根据简历路由启用独立沉浸布局；隐藏站点 Header 和导航，消除其占位。不得直接套用照片模式，因为照片模式仍有自己的沉浸导航及配色 |
| `AppRouteViewport.vue` | 仅为简历阅读增加受高度约束的容器样式；保证其他页面原有滚动行为不变 |
| `ResumeView.vue` | 继续处理加载、口令、分享及格式分支，提供常驻退出；PDF 分支取消原有 Hero / Dock 的重复占位 |
| `PdfResumeViewer.vue` | 持有当前页组和放大页状态，统一桌面/手机站内阅读；使用现有页面元数据与图片资源 |
| 新增 `ResumeSpread.vue` | 只负责传入的左右页、稳定页槽及 A 或 B 的视觉呈现；向父组件发出放大某页事件 |
| 新增 `ResumeReaderControls.vue` | 展示页组范围、首尾可操作状态和更多操作，发出上一组、下一组等明确事件；不自行加载数据 |
| `ResumeHero.vue`、`ResumeFloatingDock.vue` | 仅处理 PDF 分支的替换衔接，保留 Markdown 所需能力，不做无关重构 |

最终只实现选中的视觉方向，不把 A / B 都作为长期主题选项保留。

无需调整数据库、预览接口、上传流程、访问权限或部署镜像；无需引入 PDF.js 或翻书库。第三方接口如在实施中需要新增使用，必须届时依据实际安装版本核对公开 API 和本地解析情况。

当前还支持 Markdown 简历。它没有固定页码，本轮不对其强行切页或新增 Markdown 转 PDF 流程：进入同一沉浸框架，继续按文章方式滚动阅读，保留退出；双页分组仅针对 PDF。

## 8. 选择建议

| 选择 | 主要感觉 | 翻组呈现 | 适用偏好 |
| --- | --- | --- | --- |
| **A：极简双页展板** | 并排文档、轻量阅读台 | 短淡入或直接切换 | 优先浏览效率和正文面积 |
| **B：对开折叠书册** | 整体对开、中缝和轻微层次 | 整组轻开合 | 更强调折叠屏式视觉体验 |

**推荐 A**，因为当前首要目标是腾出阅读空间、两页完整可见；如果“像折叠屏展开”的视觉是同等重要的目标，选 B。

请在 A / B 中选择。共同规则里的“退出返回关于我”和“手机默认双页、可主动放大”也是本方案的明确建议；若希望不同语义，可随选择一起指出，再进入实现阶段。
