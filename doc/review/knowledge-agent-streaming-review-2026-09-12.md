# AI 流式输出 Review

日期：2026-09-12。范围：本次流式输出实现及其会话、停止生成、消息保存主路径。结论依据为源码审阅、安装依赖的 API 与部署镜像文件范围，不代表线上运行结果。

## 结论

本次审阅未发现 P0；确认并修复以下四类 P1。保留现有 DeepSeek 流式调用、工具分片聚合和 SSE 传输方案，不增加运行时依赖。

1. **AI 页面初始化失败**：`AiView.vue` 调用 `onUpdated` 却没有导入，进入页面会发生引用错误。已补齐导入。
2. **停止与断流收尾不完整**：服务端依赖生成器继续消费才能释放任务；生成器在 `yield` 处被关闭时可跳过 `catch`，留下 pending 消息。已将停止操作改为中止上游、保存已生成内容并释放会话；生成器关闭也会完成收尾，工具执行和最终写入前遵守取消信号。浏览器收到停止结果后关闭对应流，允许再次提问。
3. **异步请求覆盖当前会话状态**：退出登录后，列表、创建会话等请求仍可能回写旧数据；快速切换同一会话会产生并发历史请求，晚到的历史可能覆盖正在生成的消息。已统一限定请求所属的登录状态周期、复用同一会话的在途读取，并让旧流只清理自身控制器。保存文章回写发起操作的会话。
4. **完成回答被网络错误清空**：收到 completed 后正文已保存且分片已清除，但流随后报错会再次将消息改为 failed 并写入空正文。已限定本地失败处理与后续流事件只作用于 pending 消息；停止接口返回的最终记录同样不再被旧分片覆盖。解析或读取异常会中止该请求，不继续消耗上游流。
