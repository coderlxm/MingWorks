# 拾时提醒看板 · 用户验收清单

## 访问入口

- 地址：**https://remind.xmcloud.buzz**
- 登录口令：沿用 FTG 看板现有口令；登录会话独立。
- 通知渠道：现有 Telegram Bot，发送到原来配置的个人会话。
- 时间口径：北京时间；“中国工作日”包含调休安排。
- 本次范围：产品方案 P0。自然语言预填、固定生活提示配置、暗色主题及单次循环例外属于后续范围。

以下勾选项留给实际使用时确认。创建、完成、暂停、改期等操作会作用于真实提醒，请用自己的实际安排验收。

## 1. 进入页面与整体风格

- [ ] 未登录时显示口令入口，私人提醒内容不可见。
- [ ] 登录后首屏加载完成再结束开场覆盖，能直接看到今天的提醒。
- [ ] 页面采用米白、鼠尾草绿的生活日程风，滚动时顶栏保持可用。
- [ ] 桌面能够进入今天、全部提醒、循环规则、生活提醒、历史。
- [ ] 手机能够查看单列日程、打开新建表单，底栏不遮挡最后一项内容。
- [ ] 打开详情后返回，原来的筛选与列表位置保留。

## 2. 一次性提醒

- [ ] 新建一条实际需要的提醒，内容和北京时间正确。
- [ ] 使用喝水、番茄钟等快捷入口，保存前可调整内容和时间。
- [ ] 修改尚未触发的提醒，列表显示新内容和时间。
- [ ] 到点通过 Telegram 收到提醒，网页显示“已发送待确认”。
- [ ] 点击“稍后”或指定新的时间，网页显示新的计划，后续按新时间提醒。
- [ ] 在网页标记完成，提醒进入已处理／历史，Telegram 对应旧按钮不能再次改变它。
- [ ] 取消提醒后保留取消记录，原时间不再触发。
- [ ] 搜索、日期和状态筛选得到相应结果；清除筛选后恢复完整列表。
- [ ] 完成或取消的提醒可以复制为新的安排。

## 3. 循环规则

- [ ] 能新建每天、每周指定星期、每月指定日期、中国工作日的规则。
- [ ] 保存前看到规则摘要和下一次时间；规则详情能查看近期安排。
- [ ] 修改规则后，未来安排更新，已发生的历史保留原内容。
- [ ] 暂停后不再产生新的触发；恢复时显示下一次未来时间。
- [ ] 完成本次或跳过本次，只处理这一次，后续循环继续。
- [ ] 结束规则时文案说明影响整条规则，历史仍可查看。
- [ ] 对于尚未发生的预计事项，页面不把它伪装成已经发送的记录。

## 4. 生活提醒

- [ ] 维生素、上班打卡、下车分别显示今天状态与长期规则。
- [ ] 维生素“已吃”停止当天后续提醒，“稍后”显示新的 30 分钟安排。
- [ ] 维生素可调整中国工作日时间窗口和非工作日时刻；窗口尚未确定具体时刻时不显示虚构倒计时。
- [ ] 修改未发送的新安排可当天生效；当天已发送的安排保留原节奏，后续日期采用新设置。
- [ ] 下车提醒能显示次数与下一次时间，允许修改首次提醒时刻。
- [ ] “我已打卡”和“已下车”显示用户确认；到点关闭或次数上限显示自动结束。
- [ ] “今天不再提醒”只停止当天；长期关闭停止该专项后续提醒。
- [ ] 重新启用后显示未来有效安排，不立即补发过去的提醒。
- [ ] 旧日期的 Telegram 卡片不会修改今天的维生素或重新启动今天的循环。
- [ ] 睡觉、起床、咖啡、拍照和 Lu 提示展示现有规则，首期没有无效的时间编辑按钮。

## 5. 网页与 Telegram 联动

- [ ] 从 Telegram 创建或处理提醒，网页在正常同步后反映相同结果。
- [ ] 从网页修改后，Bot 的实际后续提醒与网页时间一致。
- [ ] 网页创建、编辑成功不会额外刷出一条配置成功消息，到点仍正常通知。
- [ ] 同一项已经在另一入口处理，再点旧按钮时有明确提示，不覆盖新状态。
- [ ] 操作过程中有提交反馈；失败显示原因，已填写的内容保留。
- [ ] 若业务状态已更新而 Telegram 卡片更新失败，页面明确说明两部分结果。

## 6. 历史与持续使用

- [ ] 历史能按计划日期和类型筛选，并继续加载较早记录；操作发生时间单独展示。
- [ ] 已发送、已完成、跳过、取消、主动停止、自动结束有明确区别。
- [ ] 旧记录缺少确认时间或结束原因时，页面说明信息不足，不显示推算的完成率。
- [ ] 打开编辑表单期间，后台数据刷新不覆盖草稿。
- [ ] 请求失败时能看到错误及最后数据时间；点击重新加载后再恢复同步。
- [ ] 页面切到后台后不持续读取；正常回到前台后更新当前视图。
- [ ] 跨过午夜后“今天”日期更新，昨天未处理的一次性提醒仍保留原日期。
- [ ] 退出登录后不再显示私人提醒；重新登录能正常继续使用。
