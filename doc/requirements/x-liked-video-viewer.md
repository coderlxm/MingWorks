# X 点赞视频私人播放器需求

日期：2026-10-02  
状态：供 Review；产品形态已明确为仿 TikTok 的视频流

## 1. 为什么做

我已经把自己在 X 上点赞的视频自动下载到了 Google Drive，却缺少一个舒服的观看入口。收藏下来的内容，应该能在想看的时候随手打开、连续欣赏，也能方便地找回来重看。

之前在 `erin.xmcloud.buzz` 部署过第三方竖屏播放器。根据我的实际使用反馈，它的 bug、陈旧界面和不熟悉的技术栈影响了体验，也让后续调整不够自在。

这个项目就是给我自己做一个好看的、好用的播放器。**界面美观和功能实用是第一优先级**，功能取舍围绕我的观看习惯展开。

这些视频大多是成人视频，主要用于个人欣赏。我既会看最新下载的内容，也会按当下兴趣翻看以前的内容。因此，“已看”只是记录，不代表失去观看价值；找新视频和重看喜欢的视频都属于日常主路径。

## 2. 产品形态

**采用仿 TikTok 的沉浸式视频流：打开就是视频，一屏一条，上下滑动切换，连续观看是整个产品的主路径。**

视频占据主要视觉空间，播放控制、作者和正文围绕当前视频呈现。查找旧内容等辅助操作应容易到达，结束后能自然回到观看。具体按钮位置、面板形式和视觉细节留给界面设计，不在需求阶段逐项锁死。

手机、电脑和平板都是实际使用设备，主要使用 Chrome。手机适合单手滑动，平板需要兼顾横竖屏与触摸操作，电脑适合鼠标和键盘；三种设备都应保留舒服的单视频连续观看体验，按屏幕空间适配布局。

## 3. 我希望怎样使用

### 打开就能看

进入应用后直接看到一条可观看的视频，不用先去云盘挑文件。已有归档和后续新下载的视频都应能在这里观看。

开始播放的操作要清楚、简短。加载时仍能看到完整的观看界面，并知道当前视频正在准备。

重新打开应用时，默认从最新归档的视频开始。临时切到其他应用、关闭信息面板再回来，则保留正在看的视频和进度，不因此跳到最新内容。

找新内容和重看旧内容都要方便。观看时可以容易地切换到历史归档或收藏，也可以回到最新归档。翻旧视频不应只能从最新一条逐个往前滑；应能通过归档时间定位较早的一批内容，再进入连续观看。具体入口形式留给界面设计。

### 像刷 TikTok 一样连续观看

上下滑动切换视频，手势跟手、切换明确，不会轻轻一碰就误切，也不会滑完后停在两条视频之间。

切换后只播放当前视频，上一条立即停止。连续切换多条、回看上一条、临时切到后台再回来，都应保持正确的视频、声音和进度。

相邻视频的衔接应尽量减少等待；正在看的视频不会因为新内容到达或列表更新而突然被替换。

默认按归档时间从新到旧浏览。进入历史归档、搜索结果或收藏后，连续切换和自动播放都沿用当前这组内容，不突然跳回全部视频。看过的内容仍可正常浏览和重看。

默认播完自动下一条，同时提供容易到达的“单条循环”切换，让我按当下需要决定。当前模式要清楚，切换立即反馈；循环模式下仍可主动滑动到其他视频。当前一组内容播完时明确提示，不擅自跳到另一组内容。播放模式在本次观看期间保持。

### 画面舒服，操作顺手

支持播放与暂停、拖动进度、声音控制和全屏。常用操作容易发现，触摸区域足够大，拖进度与上下切换不会互相干扰。

视频保持正确比例。横屏视频也能看完整，并方便进入适合观看的全屏状态。

控件与文字不长期挡住画面，操作时容易唤出。长正文可以展开，收起后继续观看。

电脑上可以自然地用鼠标和键盘控制播放与切换。

### 想重看时找得到，也能主动接着看

记住最近观看的视频和播放位置，关闭后再打开可以通过观看历史主动继续；这不改变重新打开默认看最新归档的行为。刷新当前观看页、查看正文、查找内容、退出全屏再回来，保留原来的观看上下文。

提供简单的观看历史，以及按作者、正文查找视频的入口。查找结果需要容易辨认，选中后直接进入观看。

“看过”和“没看过”可以帮助我找新内容，但快速划过一条不应直接算看完。该能力是否需要单独筛选入口，结合实际使用再确认。

### 把特别喜欢的视频收进收藏

收藏是必需功能。观看当前视频时能方便地收藏或取消收藏，操作即时反馈，当前收藏状态清楚可见。

收藏针对单个视频；同一推文中多个视频可以分别收藏。这是播放器里用于反复欣赏的个人精选，与 X 上原有的点赞分开记录。

收藏内容有容易到达的入口，选中后仍以相同的视频流形态连续观看，支持自动下一条和单条循环。取消收藏不应打断正在播放的视频。

收藏需持久保存，在手机、电脑和平板上访问的是同一份个人收藏。隐藏和删除不提供。

### 需要时看得到来源

当前视频能查看作者和原推文正文，并能打开原推文。同一推文的多个视频都可以观看，来源信息保持一致。

这些信息帮助理解和找回内容，观看时仍以画面为主。

## 4. 界面要达到的品质

美观是这次重做的核心价值，需要从第一版就体现在完整界面中。

建议以适合观影的深色基调展开设计，用统一的字体、间距、图标和轻量控件形成清爽、精致的整体观感。最终配色和样式在设计时确认。

重点打磨以下细节：

- **画面与信息的关系**：视频突出，作者和正文清楚，操作区不会喧宾夺主。
- **滑动与切换的手感**：过渡自然，反馈及时，动画服务于操作。
- **手机实际可用空间**：适应屏幕安全区和底部手势区，常用按钮单手容易触达。
- **平板与电脑的空间利用**：适应横竖屏和宽屏，画面大小、信息与操作区比例协调，避免简单放大手机布局。
- **不同视频比例**：竖屏、横屏及其他比例都呈现得协调。
- **连续使用的一致性**：播放、加载、查找、返回都保持稳定的界面框架，不整页闪烁或反复重置。

## 5. 现有内容怎样接进来

当前源码和服务器配置表明，视频已经归档到 Google Drive 的 `X点赞视频` 目录。下载服务保留了作者、正文、推文 ID、媒体标识、云端路径和上传时间，可以作为播放器的内容基础。

播放器沿用这批内容和现有自动下载链路。已归档视频应能被找到并播放，后续新增视频也能自然进入视频流。归档时间与实际点赞时间需准确区分。

Google Drive 文件如何支持流畅起播和进度拖动、如何与已有记录关联，需要后续结合实际环境确定。这些是实现观影体验必须解决的问题，需求文档不预先指定传输或存储方案。

内容继续供我本人访问，日常进入播放器的步骤应简短。前端采用我熟悉的 Vue 3 生态，方便以后自己调整界面和功能。

## 6. 使用中不能出现的体验问题

- 切换后上一条还在发声，或画面、正文、进度对应不同视频。
- 查看信息或返回应用后，突然跳回开头、丢失当前位置。
- 更新内容时打断正在观看的视频。
- 视频加载失败却一直转圈，或把读取失败显示成没有内容。

遇到无法播放的视频，界面应明确说明当前失败，让我仍可主动切换其他视频。问题应能被看见并回到根因处理。

## 7. 已确定的日常使用方式

本轮已明确：

1. 手机、电脑和平板都会使用，以 Chrome 为主要浏览器。
2. 重新打开默认看最新归档，也要方便定位历史内容和重看收藏。
3. 默认自动下一条，可随时切换单条循环。
4. 需要收藏，不需要隐藏和删除。

观看历史和具体播放进度是否也需要跨设备接续，尚未明确；收藏按各设备共用同一份来设计。随机播放不是本轮已确认需求。

判断这个产品是否做对，最终看我能否愿意经常打开它：看起来舒服，刷起来顺手，想看的内容找得到，离开回来也能接得上。

本次仅形成需求文档，供 Review 后继续收敛。
