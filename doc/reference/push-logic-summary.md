# 推送消息逻辑速查

整理日期：2026-10-02。依据当前工作区源码；每日英语的新频率尚未提交部署，其余不据此断言线上配置。固定时间均为北京时间；工作日包含调休补班日，非工作日包含周末和节假日。

## 可配置提醒

生活提醒可在提醒管理页调整或关闭。下列时间为代码默认值，实际以数据库中保存的设置为准。

| 消息 | 默认规则 | 后续交互 |
| --- | --- | --- |
| 下车提醒 | 工作日 09:22 开始 | 每 2 分钟一次，最多 3 次；确认或停止后结束 |
| 上班打卡 | 工作日随 09:55 新闻发送 | 未结束时 09:59 再提醒；10:00 自动结束，不新增截止消息 |
| 维生素 | 工作日 20:45–21:00 随机开始；非工作日 18:30 | 每 30 分钟提醒至当天结束；可确认、延后 30 分钟或停止；确认后删除当日提醒消息 |
| 一次性提醒 | 用户指定时间或快捷倒计时 | 到点发送；可完成或延后；重启时错过的时间不自动补发 |
| 循环提醒 | 用户指定周期、时间与时区 | 每次发送后继续下次；支持中国工作日过滤及暂停/结束，错过的周期不补发 |

健身计划的自动推送目前关闭；快捷“健身”倒计时仍属于一次性提醒。

## 订阅与事件通知

轮询只是获取数据，满足发送条件才会推送。

| 消息 | 触发或轮询 | 实际发送条件 |
| --- | --- | --- |
| AV 订阅更新 | 每天 07:30、15:30、23:30；也可手动检查 | 订阅出现未推送内容；演员发作品图文/图集，厂商等发最新批次摘要，按历史记录去重 |
| Steam 价格提醒 | 每天 02:15、08:15、14:15、20:15；也可手动检查 | 价格从目标价以上降至目标价以内，或已达标后进一步降价 |
| start.gg 赛事动态 | 开启监控后每 15 分钟；活跃赛事追加约每 2 分钟检查 | 关注选手、种子或决赛阶段有新动态时汇总发送；按比赛记录去重；新游戏项目询问是否关注，无项目或全部完赛时通知并停止轮询 |
| Journal 留言/评论 | 访客提交成功后立即触发 | 发送作者、内容摘要及管理按钮；点赞不发通知 |
| Journal 朋友投稿 | 投稿成功后立即触发 | 发送投稿人、媒体数量、文字摘要及查看入口 |
| 备份异常 | 每天 05:10 获取备份状态 | 仅新出现的失败告警；连续失败不重复，恢复后再失败可再次告警 |
| AV 源站异常 | AV 检查时至少两个目标失败 | 发送异常摘要；相同全局告警至少间隔 6 小时 |
| Bot 服务异常退出 | systemd 的 OnFailure 触发 | 发送服务名和异常退出时间 |
| 部署成功 | Bot 或 Journal 对应发布完成后 | 发送发布时间、提交标识及服务/发布范围 |

手动命令、按钮、视频下载和 Journal 保存操作另有即时回执或原消息更新，随用户操作触发，不属于定时推送。GitHub 的 `Daily News Push` workflow 目前仅支持手动触发，通过单次入口按执行时间选择消息；自动定时主入口是常驻 Bot。
