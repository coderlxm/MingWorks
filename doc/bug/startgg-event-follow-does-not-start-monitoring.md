# Bug：仅关注本届赛事后未启动目标赛事监控

## 严重程度

高。用户已明确选择关注正在进行的赛事，界面也反馈关注成功，但目标赛事实际上没有进入监控，随后轮询还会被旧赛事状态错误关闭，导致核心提醒功能失效。

## 发现时间

2026-09-12 18:00（Asia/Shanghai）

## 用户操作与意图

1. 点击「比赛了」。
2. 在赛事确认卡中点击「仅关注本届赛事」。
3. 目标赛事为 `Ultimate Fighting Arena 2026`。
4. 用户意图是只监控本届 UFA 2026，而不是长期关注该游戏的后续赛事。

## 实际结果

- Telegram 消息被编辑为「仅关注本届赛事：Ultimate Fighting Arena 2026」。
- 线上数据库成功写入该赛事的临时关注记录，并将轮询状态设为开启。
- 目标赛事没有进入 `startgg_watch_events` 实际监控列表。
- 18:00 定时任务仍读取到两场残留的旧赛事，且两场均为 `COMPLETED`。
- 定时任务据此发送「start.gg 当前订阅赛事已结束，自动轮询已关闭。」并关闭轮询。
- UFA 2026 没有获得后续同步和赛事提醒。

## 期望结果

点击「仅关注本届赛事」后，UFA 2026 应立即进入实际监控主路径；后续结束判断必须基于当前关注并已同步的赛事，不应被旧赛事状态提前终止。

## 已核实根因

`src/bot/interactive.ts` 的赛事关注回调只写入 `startgg_event_interest_overrides`、删除待确认项并开启轮询，没有立即将目标赛事加入实际监控列表，也没有立即执行赛事同步。

`src/scheduled/jobs.ts` 的固定轮询在执行赛事发现与同步前，先读取现有 `startgg_watch_events` 判断是否全部结束。由于列表中仍保留两场已完成的旧赛事，任务直接关闭轮询并返回，新增的 UFA 2026 关注记录没有机会被转换为实际监控赛事。

## 线上证据

- UFA 2026 临时关注记录创建时间：`2026-09-12T09:55:31.854Z`。
- UFA 2026 结束时间：`2026-09-13T21:59:00.000Z`，事发时仍在进行期内。
- 轮询状态在同一时间更新为开启。
- 当时实际监控列表中的活动记录仍是 `World Warrior 2026 - Japan 3` 和 `FATAL FURY Asia League｜China Qualifier`，两者状态均为 `COMPLETED`。
- 18:00 定时任务发送赛事已结束消息并关闭轮询。

## 修复边界

修复应覆盖「发现赛事 → 用户选择仅关注本届 → 目标赛事进入监控 → 首次检查 → 后续轮询 → 赛事结束后关闭」的完整主路径，不能只删除旧数据或针对 UFA 2026 增加特例。
